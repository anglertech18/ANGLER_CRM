# Daily Report Module - Automated Email Report

## Overview

The **Daily Report** is a **Reports** submodule in the CRM application.

This module is **read-only** and serves as a reference for users to view the Daily Report that is automatically generated by the system.

Users **cannot** manually create, edit, or send Daily Reports.

The system will automatically generate and send the Daily Report every day using a scheduled job (Cron Job).

---

# Daily Report Enable/Disable

Not every user should receive a Daily Report. Each user has a
`daily_report_enabled` flag (default `false` for new users), managed from the
Target Management (`admin/Users`) screen — a quick toggle in the table and a
checkbox on the Add/Edit User form. This is a separate setting from the
user's Active/Inactive status; a disabled/intern/test user account is
excluded purely by leaving this flag off, not by deactivating the account.

---

# Automated Report Flow

Every day at the configured schedule:

1. Fetch only users with `daily_report_enabled = true` (a dedicated opt-in
   flag, independent of the user's `status`/`is_active` — an active user with
   the flag off is still excluded, and vice versa is not possible since
   disabling the flag is the only gate).
2. Identify the products mapped to each user (`UserProductTarget`), and
   resolve each product's company from the existing Product → Company mapping
   (`product.company_id`) — **not** from the user's own `company_id`, since a
   single BDE can carry products for more than one company.
3. Group the user's products by resolved company. A BDE with products across
   multiple companies gets **one report row and one email per company**, each
   sent to that company's own recipient.
4. Within each company's report, fetch the user's current leads for each
   mapped product **filtered to quadrant Q1/Q2/Q3/Q4 only** (not
   date-filtered otherwise), grouped by Quadrant. Leads with no quadrant, or
   with quadrant Nurturing/Order Won/Order Lost, are excluded from this
   section — lead `status` is never used as the inclusion filter.
5. Fetch the product-wise SWAT Performance for the report date only.
6. Fetch today's Sales Engagement activity (follow-ups logged today, scoped
   to that company's products) as a separate flat section.
7. Generate the Daily Report per company.
8. Send each company's report automatically to that company's recipient.

# Email Recipients

The report is sent based on each product's mapped company (Product → Company
mapping), not the employee's own company — a BDE can have products across
multiple companies and gets one email per company.

The recipient email is stored on **Company Master**
(`company.report_recipient_email`) instead of hardcoded, so it can be changed
without modifying the application. A company with no recipient configured
still gets its report row logged, marked `failed`, with an error message —
it's just not emailed.

# Report Structure

The report should be grouped **Company → Employee → Product → Quadrant**.

Greeting: `Good Evening Sir,`

## Employee

**Simsone**

---

## Company: Trinetra Wireless

## Product: FMS

### Lead Activity (current leads, not date-filtered — grouped by Quadrant: Q4, Q3, Q2, Q1 only)

| Lead Name   | Quadrant | Sales Engagement Remarks | Sales Engagement Date | Status |
| ----------- | -------- | ------------------------- | ---------------------- | ------ |
| ABC Company | Q4       | Customer requested demo   | 12/08/2026              | Open   |
| XYZ Company | Q3       | Follow-up scheduled       | 10/08/2026              | Open   |

Only leads currently in quadrant Q1-Q4 are included; leads with no quadrant,
or in Nurturing/Order Won/Order Lost, are excluded regardless of `status`.
Remarks/Date come from the lead's most recent Follow-up Log entry (`—` if none
yet). Status is derived from the lead's quadrant: `Order Won` → Won,
`Order Lost` → Lost, everything else → Open — it is a display column only and
never controls inclusion. A product with no current Q1-Q4 leads shows
"No records available for today." instead of an empty table.

### SWAT Performance (filtered to the report date only)

| Activity            | Achieved/Target |
| -------------------- | ---------------: |
| Calls                |            10/25 |
| Activities           |             5/12 |
| Email Campaign       |            0/530 |
| LinkedIn Conn Sent   |             2/18 |
| Demo                 |              1/3 |
| Proposal             |              1/2 |
| Direct Visit         |              2/4 |

All 7 metrics are always shown, zero-filled when no SWAT row exists for the
user/product/date — the section is never skipped or filtered down.

## Today's Sales Activity

A flat, date-filtered section (across all products) showing only follow-ups
logged **today** by the employee — separate from the Lead Activity tables
above, which show all current leads regardless of date.

| Lead Name   | Quadrant | Sales Engagement    | Status |
| ----------- | -------- | -------------------- | ------ |
| ABC Company | Q4       | Requirement Call     | Open   |

Shows "No records available for today." when the employee logged nothing
today.

---

# Email Layout

The email should have a clean, professional HTML layout.

* Greeting ("Good Evening Sir,") and company name at the top.
* Product-wise sections, each with Lead Activity (grouped by Quadrant) and
  SWAT Performance.
* A "Today's Sales Activity" section at the end, across all products.
* "Regards, CRM System" footer.
* Professional spacing, colors, and typography suitable for management review.

---

# Daily Report Module UI

The Daily Report page should resemble an **email preview** instead of a traditional data entry form.

## Features

* View generated Daily Reports.
* Filter by Date.
* Filter by Product.
* Preview the exact email sent by the system.
* Print Report.
* Export as PDF.

## Restrictions

Users **cannot**:

* Create Daily Reports.
* Edit Daily Reports.
* Delete Daily Reports.
* Send emails manually.

---

# Expected Outcome

* Daily Reports are generated automatically every day.
* Emails are sent automatically to the appropriate Company Administrator based on the employee's company.
* Reports are grouped by **Employee** and **Product**.
* Each product includes:

  * Lead Activity Report
  * SWAT Activity Summary
* The Daily Report module serves as a read-only email preview for user reference.
* The UI should resemble a professional email template rather than a standard form.
